# 손으로 가르친 동작 기록·복귀·재생

`nero_teach.py`는 손으로 유도한 관절 경로를 저장하고, 기록의 역방향으로 시작 자세에 복귀한 다음 정방향으로 재생하는 도구입니다. Nero 펌웨어 1.12 이상의 leader 관절 패킷 또는 명시적으로 모드 6이 확인된 일반 관절 패킷을 사용합니다. 가상 CAN으로 검증했으며 실제 로봇의 손 유도 모드·기계적 거동은 별도 확인이 필요합니다.

첫 버전은 **물체에 접촉하지 않는 작은 공중 동작**을 대상으로 합니다. 기록한 경로를 관절 웨이포인트로 근사하여 낮은 속도로 재생합니다. 원래 손동작의 속도·리듬·접촉력은 재현하지 않습니다.

## 1. disable 대신 손 유도 모드 사용

제조사 SDK에는 `set_leader_mode()`가 zero-force drag 모드로 정의되어 있습니다. 이 도구는 이미 활성화된 팔에 해당 모드 전환을 요청합니다. **disable을 보내거나 비활성화된 팔을 억지로 움직이는 방식이 아닙니다.**

- `record --execute`: 사전 검사 → 교시 역할 요청 → 교시 데이터 출처 확인 → 기록 → 정지 관찰 → 제어 모드 복귀 확인.
- 진입 요청은 SDK의 leader 역할 설정 패킷만 사용하고, 일반 CAN 피드백을 미리 끄지 않습니다. 역할 전환이 적용되지 않아도 관측을 유지하기 위한 단일 로봇용 처리입니다. 일반 피드백을 쓰려면 새 상태에서 `ctrl_mode=6`이 명확히 확인되어야 합니다. `ctrl_mode=1`의 일반 관절값을 교시 기록으로 대체하지 않습니다.
- 팔과 도구를 지지한 상태에서 진입·종료합니다. 모드 전환만으로도 자세가 달라질 수 있습니다.
- 전용 leader 패킷 4개 또는 연동 교시 모드(6)에서 새 일반 관절·상태·드라이버 피드백을 사용합니다. 이는 교시 역할/데이터의 확인이며 손 유도 힘이나 중력 보상 성능을 센서로 검증하는 기능은 아닙니다.
- 모드 전환 후 손으로 움직이기 어렵다면 힘으로 밀지 말고 멈추세요. `control --execute`로 제어 복귀를 시도하고 실제 장비/도구 설정을 확인합니다.
- 자동 enable·disable·reset은 하지 않습니다. 자동 비활성화는 팔이 처지는 원인이 될 수 있으므로 사용자가 기존 절차에 따라 수행합니다.
- USB-CAN은 이 로봇 하나에 연결된 구성을 전제로 합니다. 다른 제어 프로그램이나 다른 로봇이 같은 CAN 버스에서 관절 명령을 보내지 않게 합니다. leader 패킷은 일반 관절 명령과 CAN ID를 공유합니다.

근거: [제조사 Nero API 문서의 Leader/Follower 설명](https://github.com/agilexrobotics/pyAgxArm/blob/master/docs/nero/nero_api.md#leader-follower-arm).

## 2. 명령 종류

| 명령 | 기본 동작 | `--execute`를 붙인 경우 |
| --- | --- | --- |
| `record` | 설명만 표시, 연결하지 않음 | 손 유도 모드로 전환하여 기록하고 제어 모드로 복귀 |
| `inspect 경로` | 파일과 재생 경로를 오프라인 검토 | 여전히 검토만 수행 |
| `home 경로` | 복귀 방식과 시작 자세를 오프라인 검토 | 현재 자세에서 기록의 시작 자세로 관절 이동 한 번(기본). `--return-path recorded`면 기록을 거꾸로 따라감 |
| `replay 경로` | 정방향 재생 경로를 오프라인 검토 | 기록의 시작 자세에서 경로 재생 |
| `control` | 설명만 표시 | 손 유도 상태에서 정지 확인 후 제어 모드 복귀 시도 |
| `prepare` | 설명만 표시, 연결하지 않음 | 모터 7개 비활성 상태에서만 MOVE_J·위치/속도 제어 준비. 자동 enable/disable 없음 |

`home`은 제조사 영점이나 절대 XYZ `(0, 0, 0)`으로 이동하는 기능이 아닙니다. **선택한 기록의 첫 관절 자세**로 돌아옵니다. 로봇 영점 설정은 바꾸지 않습니다.

## 3. 첫 실습: 기록 → 검토 → 복귀 → 재생

프로젝트 루트에서 `.venv`를 사용합니다. 팔 전체와 도구가 움직일 공간을 확인하고, 처음에는 손끝을 공중에서 몇 mm 옮기는 정도의 작은 동작으로 시작합니다. 다른 로봇 제어 프로그램과 상태 조회 프로그램은 종료합니다.

### ① 기존 방식으로 활성화

```powershell
python nero_read_status.py
python nero_enable.py
```

정상 CAN 제어 및 모터 7개 활성화가 확인되어야 기록 전 검사를 통과합니다. `nero_disable.py`는 실행하지 않습니다.

모터는 모두 켜졌는데 `NO_SOLUTION`이 남으면 `python nero_recover.py --execute`로 복구를 시도할 수 있습니다. 현재 위치를 직선 목표로 보내고, 그래도 남으면 플랜지를 1mm 내렸다 되돌립니다(관절 목표로는 이 표시가 지워지지 않는 것을 2026-11-17에 확인). **실제 NORMAL 응답을 확인한 뒤** 기록하세요. [복구 안내](RECOVERY_KO.md)에 확인된 로그와 실패 시 동작을 정리했습니다.

단, 상태의 `mode_feedback`이 `MOVE_MIT(6)` 또는 `MOVE_CPV(5)`라면 아래의 **MIT/CPV 상태에서 기록 진입이 막힌 경우** 절차를 먼저 따릅니다. CAN 제어 여부인 `ctrl_mode`와 이동 종류인 `mode_feedback`은 서로 다른 항목입니다.

### ② 손으로 움직이며 10초 기록

```powershell
python nero_teach.py record --output data/nero_teach/demo01 --duration 10 --execute
```

실행 후 3초 준비 시간을 주고 상태를 검사합니다. 팔과 도구를 지지한 채 **`기록 시작` 출력부터** 천천히 움직이세요. 10초가 끝나면 팔을 멈추고 계속 지지합니다.

그 뒤 관절 변화가 0.5초 동안 0.05도 이내이고 새로운 패킷이 충분한지 관찰합니다. 정지가 확인되면 follower 역할을 요청하고, 기존 P/J/L/C 이동 종류를 유지하는 유효한 CAN 제어 요청을 보냅니다. 새 피드백에서 `ctrl_mode=1`을 확인해야 복귀 완료입니다. 잠시 모드 6이 남아 있으면 최대 3초 기다리며, 계속 남아 있으면 실패합니다. 이 소프트웨어 관찰이 물리적 정지를 보장하는 것은 아닙니다.

현재 SDK의 공개 모드 전환 함수는 일반 CAN 피드백을 끄는 설정도 보냅니다. 이 도구는 역할 설정 패킷을 직접 사용해 그 부작용을 피하고, 관측 재개용 메시지와 제어권 복귀용 메시지를 구분합니다. 관측 재개 시 이동 모드/MIT 필드를 변경하지 않음으로 보내며, 실제 제어권 요청 시에는 확인한 기존 P/J/L/C 종류와 위치·속도 제어를 명시합니다. 두 경우 모두 속도 비율 5%이며 이동 목표·모터 활성화·비활성화·reset 명령은 보내지 않습니다. MIT/CPV 상태에서 임의로 위치 제어로 바꾸지 않습니다. SDK 내부 메시지를 사용하는 부분이므로 SDK를 교체하면 다시 검증해야 합니다.

`기록 완료. 제어 모드 복귀를 확인했습니다.`가 출력될 때까지 지지 상태를 유지합니다. 끝나면 팔은 마지막 자세에 있고 모터는 활성화 상태로 남습니다. 여기서는 자동으로 시작점에 돌아가지 않습니다.

같은 폴더는 덮어쓰지 않습니다. 다시 기록할 때는 `demo02`처럼 다른 이름을 사용합니다. `--output`을 생략하면 날짜·시각·ID로 이름을 정합니다.

### ③ 기록과 재생 경로 검토

```powershell
python nero_teach.py inspect data/nero_teach/demo01
```

원본 샘플 수, 재생 웨이포인트 수, 관절별 최대 움직임 범위, 시작/끝 관절각을 표시합니다. 이 명령은 로봇에 연결하지 않습니다. 상세 원본은 `joints.csv`와 `trajectory.json`에서 볼 수 있습니다. 시작/끝이 비슷하더라도 중간에 돌아오는 동작이 있을 수 있으므로 경로 전체를 확인합니다. 충돌 검사는 하지 않습니다.

### ④ 시작 자세로 복귀

먼저 미리보기:

```powershell
python nero_teach.py home data/nero_teach/demo01
```

실제 실행:

```powershell
python nero_teach.py home data/nero_teach/demo01 --execute
```

2026-11-18부터 기본 복귀 방식은 **기록의 첫 관절각으로 관절 이동 한 번**입니다(`--return-path direct`). 모든 관절이 같은 비율로 움직여 함께 도착하며, `nero_home.py`와 같은 방식입니다. 실행하면 가장 많이 도는 관절 각도, 플랜지 이동 거리, 팔꿈치·손목·플랜지의 최저 높이를 보여 주고 3초 뒤 출발합니다(그 사이 Ctrl+C로 취소). 최저 높이가 50mm(`--min-z-mm`)보다 낮으면 이동하지 않습니다. 단, 이미 50mm보다 낮은 자세에서 출발하면 출발 높이보다 더 내려가지만 않으면 허용합니다(`nero_home.py`와 같은 규칙). 현재 자세가 기록의 끝 자세가 아니어도 됩니다. 이미 시작 자세에서 최대 0.1도 이내이면 이동을 보내지 않습니다.

XYZ 좌표가 아니라 관절각으로 돌아가는 이유: 재생은 관절 경로를 따라가므로 시작할 때 관절 7개가 기록의 첫 자세와 0.5도 안으로 같아야 합니다. 7축이라 같은 XYZ에도 팔꿈치 자세가 여러 개라서, 좌표 이동(`nero_move_to.py`, `nero_goto.py`)으로는 이 조건을 보장할 수 없습니다.

직접 이동은 손으로 지나가지 않은 공간을 지나갑니다. 주변에 물건이 가까워 확인된 길로만 돌아가야 하면 `--return-path recorded`를 붙입니다. 이때는 이전처럼 기록을 거꾸로 따라가며, 현재 자세가 기록의 끝 자세에서 0.5도 안이어야 합니다. 웨이포인트마다 약 0.85초씩 걸려 느립니다(teach_test02: 201개, 약 3분).

### ⑤ 기록한 동작 재생

미리보기:

```powershell
python nero_teach.py replay data/nero_teach/demo01
```

실제 재생:

```powershell
python nero_teach.py replay data/nero_teach/demo01 --execute
```

현재 자세가 기록의 시작 자세에서 각 관절 최대 0.5도 이내여야 합니다. 맞지 않으면 자동으로 크게 이동하지 않고 중단합니다. 정상 재생은 기록의 끝 자세에서 종료됩니다.

## 4. 기록 후 자동 복귀 / 여러 번 재생

기본 흐름을 검증한 뒤 사용할 수 있는 옵션입니다. `--execute`와 함께 쓰면 실제 이동을 추가합니다.

기록 종료와 제어 복귀 확인 후 시작 자세로 돌아오기:

```powershell
python nero_teach.py record --output data/nero_teach/demo02 --duration 10 --return-to-start --execute
```

제어 복귀 확인 뒤 `3초 후 시작 자세로 복귀합니다(direct)`가 출력됩니다. 이때 팔에서 손을 떼고 공간을 비웁니다. 그 뒤 이동 전 검사를 거쳐 복귀합니다. 대기 중 `Ctrl+C`로 복귀를 취소할 수 있습니다.

시작 자세에서 재생 3회. 각 재생 사이와 마지막에 시작 자세로 돌아오기:

```powershell
python nero_teach.py replay data/nero_teach/demo02 --cycles 3 --return-to-start --execute
```

이때 동작은 **재생 → 복귀 → 재생 → 복귀 → 재생 → 복귀**입니다. 복귀는 기본적으로 관절 이동 한 번이고, `--return-path recorded`를 붙이면 기록을 거꾸로 따라갑니다. 복귀도 실제 동작입니다. 접촉 중인 표면을 긁으며 되돌아오는 용도로 사용하지 않습니다. `--return-to-start`가 없으면 마지막에는 끝 자세에서 종료됩니다.

## 5. 저장되는 정보

2026-11-17 수정: 기록 경과 시간은 고해상도 `perf_counter()`로 측정합니다. Windows/Python 3.12에서 첫 두 샘플의 `monotonic()` 경과 시간이 모두 0으로 저장되는 사례가 있었으며, 중복·역전 시간은 새 기록에 쓰지 않습니다. 파일 검사는 여전히 중복·역전 및 0.5초 이상 공백을 거부하고 문제 샘플 번호와 간격을 출력합니다. 실제 누락을 검사에서 무시하지 않습니다.

`teach_test01`의 해당 문제는 원본 CSV의 증가하는 `host_epoch_s`와 CAN 패킷 시각을 대조해 확인했습니다. 원본은 보존했고 `teach_test01_timing_fixed` 사본의 경과 시간만 CSV 시각 기준으로 복원했습니다. 223개 관절값과 패킷 시각은 그대로입니다. 사본 JSON의 `timing_repair`에 원본 경로·해시·방법을 남겼습니다. 이 파일의 관절별 최대 범위는 약 39.595도이므로 오프라인 검토에는 `--max-span-deg 45`가 필요합니다. 이 수리는 다른 기록의 실제 통신 공백을 복원하거나 충돌 안전성을 확인한 것이 아닙니다.

```text
data/nero_teach/demo01/
  trajectory.json  # 관절각(rad)·경과 시간·원시 수신 시각, 완료/제어복귀 여부
  joints.csv       # Excel에서 확인할 원본 관절 기록(rad/deg)

data/nero_teach/runs/<날짜_시각_ID>/
  meta.json        # 재생한 파일과 웨이포인트(rad), 실행 모드
  robot.csv        # 재생/복귀 중 일반 위치·관절각·시간 기록
  events.jsonl     # 웨이포인트 요청/도착 이벤트
  summary.json     # 완료/중단, 관절 목표 오차, 완료한 웨이포인트
```

교시 중 데이터 출처는 `trajectory.json`의 `source`에 저장합니다. `leader_packets`는 전용 관절 패킷, `normal_joint_packets_in_linkage_mode`는 새 `ctrl_mode=6` 상태와 함께 수신한 일반 관절 패킷입니다. 한 기록 안에서 출처를 임의로 바꾸지 않으며, CSV의 `component_12/34/56/7_epoch_s`는 선택한 출처의 수신 시각입니다. 일반 플랜지 XYZ가 계속 들어온다고 가정하지 않으므로, 처음 모드 전환 전 플랜지 위치만 참고 정보로 저장합니다. 손 유도 중 XYZ 궤적을 이 파일에 실측 저장했다고 해석하지 않습니다.

재생 중 `robot.csv`의 XYZ는 플랜지 위치입니다. 장착한 도구 끝 TCP는 별도 보정이 필요합니다. `summary.json`의 `max_joint_error_deg`는 로봇 피드백 기준 최대 관절 목표 오차입니다. 목표 XYZ를 계측하지 않은 관절 재생에서는 `max_endpoint_error_mm`가 `null`입니다. 오차가 0이라는 뜻이 아닙니다.

기본 생성 경로 `data/nero_teach/`는 Git에서 제외합니다. 다른 저장 경로를 지정했다면 그 경로의 Git 제외 여부도 확인합니다.

### 실행 진단 로그

실제로 실행하는 명령은 `data/nero_teach_logs/날짜_시각_ID.jsonl`에 실행 시작, 연결 후 상태, follower 요청 전후 상태, 완료 또는 실패 사유를 저장합니다. `record`가 파일 생성 전에 거부되거나 단독 `control`이 실패해도 이 로그는 남습니다. 미리보기와 오프라인 검토에서는 생성하지 않습니다. 실행 시 로그 경로를 출력하며, 새 교시 파일에는 `diagnostic_log`로 해당 경로도 저장합니다. 이 폴더 역시 Git에서 제외합니다.

각 상태에는 `ctrl_mode`, `mode_feedback`, 모터 활성화와 피드백 최신 여부가 들어갑니다. leader 상태에서는 일반 상태가 오래됐거나 없을 수 있으므로 `status_fresh`, `driver_feedback_fresh`를 함께 확인해야 합니다. 이 로그는 상태 진단용이며 교시 관절 궤적이나 모든 CAN 프레임을 대체하지 않습니다. PowerShell 명령 이력은 실행한 명령만 저장하므로 과거 터미널 출력을 복원할 수 없습니다.

## 6. 경로 재생의 정확한 의미

- 원본은 기본 목표 20Hz로 폴링합니다. 실제 주기는 달라질 수 있으며, 모든 관절 패킷이 새로 들어온 샘플만 추가합니다. 여러 CAN 메시지는 완전히 동시 측정된 데이터가 아닙니다.
- 먼저 시간에 따른 관절각을 직선으로 근사하며 기본 0.1도보다 크게 벗어나는 지점을 남깁니다. 관절별 전체 범위는 기본으로 검사하지 않습니다(`--max-span-deg`로 지정한 경우에만).
- 남긴 지점 사이가 각 관절 기준 최대 2도를 넘으면 관절 공간에서 보간해 작은 목표로 나눕니다. 기록 위치가 SDK 관절 제한을 넘는 경우는 거부하며, 제한값을 임의로 넓히거나 목표를 조용히 잘라내지 않습니다.
- 2026-11-19부터 기본 재생은 **연속 재생**(`--replay-mode smooth`)입니다. 웨이포인트를 이은 관절 경로 전체를 한 번에 따라가며, 팔의 현재 위치보다 경로 위로 약 2도 앞선 지점을 목표로 초당 100번 갱신해 `move_j()`로 보냅니다. 점마다 멈추지 않습니다. 끝점에서는 최대 목표 오차 0.1도 미만을 3회 확인합니다. 관절이 경로에서 5도 넘게 벗어나거나, `--timeout` 동안 진행이 없으면 중단하고 급정지 정책을 따릅니다.
- 컨트롤러는 모든 관절을 같은 속도로 돌리므로, 조금만 움직이는 관절은 비율을 맞추느라 짧게 가고 서기를 반복합니다. 그래서 약간의 떨림이 남을 수 있습니다(관절 이동 `together` 방식과 같은 원리).
- 이전 방식(`--replay-mode waypoints`)은 각 웨이포인트마다 목표 전송 → 도착 확인 → 0.5초 정지 관찰을 반복합니다. teach_test04(194개)에서 7% 속도로 186초가 걸렸고, 같은 경로의 연속 재생은 약 23초로 계산됩니다(가장 많이 도는 관절 기준 경로 길이 276도 ÷ 약 12.6도/초).
- 어느 방식이든 **원본 시간이나 속도를 그대로 재생하지 않습니다.** 재생 속도는 `--speed`로 정합니다.
- 7개 관절 경로를 따라가도 Cartesian 궤적이 완전히 동일하다는 보장은 없으며, 단순화·도착 허용 오차·장착물 상태가 결과에 영향을 줍니다. 장애물·자기충돌·접촉력은 자동 검사하지 않습니다.
- 즉각 반응하는 `move_js()`나 관절 토크/MIT 명령은 사용하지 않습니다.

## 7. 옵션

| 옵션 | 기본값 | 의미 |
| --- | --- | --- |
| `--duration` | 10 | record: 1~120초, 이후 정지 관찰 구간이 추가됨 |
| `--sample-hz` | 20 | record: 목표 폴링 5~50Hz. 종료 정지 관찰 구간의 주기는 다를 수 있음 |
| `--simplify-deg` | 0.1 | 경로 단순화 허용 오차. 0.01~0.5도 |
| `--step-deg` | 2 | 관절 웨이포인트 간격. 0.2~4도 |
| `--replay-mode` | smooth | smooth: 경로를 멈추지 않고 연속으로 따라감 / waypoints: 점마다 멈췄다 가는 이전 방식 |
| `--max-span-deg` | 360 | 관절별 전체 범위 한도(0~360). 기본은 사실상 제한 없음이며, 큰 동작을 막고 싶을 때만 지정 |
| `--timeout` | 30 | 목표에 가까워지지 않은 채 기다리는 최대 시간(초) |
| `--return-path` | direct | 시작 자세로 돌아가는 방식. direct: 관절 이동 한 번 / recorded: 기록을 거꾸로 따라감 |
| `--speed` | 7 | 속도 비율(%), 1~20. 재생과 복귀 모두에 적용 |
| `--min-z-mm` | 50 | direct 복귀 중 팔꿈치·손목·플랜지의 최저 허용 높이(mm) |
| `--cycles` | 1 | replay: 1~10회. 사이에 시작 자세로 복귀 |
| `--return-to-start` | 꺼짐 | record/replay: 완료 후 역경로로 시작점 복귀 |
| `--channel` | 0 | Windows USB-CAN 채널 |
| `--firmware` | 자동 조회 | control 전용. 이미 확인한 v112/v120/v121을 지정하면 펌웨어 조회를 생략 |

첫 검증에서는 기본값을 사용하고 작은 공중 동작을 기록하세요. 단순화 허용 오차는 관절 경로에 대한 설정이며, 도구 끝 위치의 mm 정확도 설정이 아닙니다.

### 기록 범위 한도

2026-11-18부터 기본 한도는 360도(사실상 제한 없음)입니다. 그 전에는 기본 30도, 최대 90도였습니다. 이 값은 로봇 관절의 기계적 한도가 아니라 소프트웨어 한도입니다. 각 관절에 대해 **기록 중 최댓값 - 최솟값**을 계산한 값으로, 1회 명령의 각도나 7개 관절의 합을 뜻하지 않습니다. 일반 기록은 저장할 수 있지만 `inspect`·`home`·`replay`의 경로 생성에서 이 값을 검사합니다. `--return-to-start`가 없는 일반 `record`에서 범위를 넘겼다고 저장을 중단하는 것은 아닙니다.

예를 들어 `demo_move01`은 정상 완료된 252개 샘플이며 J4가 2.456~34.035도로 움직여 범위가 31.579도였습니다. 다음 오프라인 검토는 통과했고 관절 웨이포인트 105개가 생성됐습니다.

```powershell
python nero_teach.py inspect data/nero_teach/demo_move01 --max-span-deg 45
```

(위 예시는 한도가 30도이던 때의 것입니다. 지금은 옵션 없이도 통과합니다.) 한도를 직접 지정하면 해당 `home`·`replay` 명령에도 같은 값을 붙여야 합니다. 옵션은 각 실행에만 적용되며 기본값을 저장하지 않습니다. SDK의 절대 관절 제한, 기본 웨이포인트 간격 2도, 시작 자세 확인과 오류 검사는 유지됩니다. 범위를 늘려 검토를 통과하는 것은 충돌이나 손 유도 힘을 검증한 것이 아닙니다.

### 손을 떼면 시작 자세 쪽으로 돌아오는 경우

손 유도는 시작점 자동 복귀 기능이 아닙니다. 자동 시작점 복귀는 사용자가 `--return-to-start`를 지정했을 때 기록과 제어 복귀가 끝난 뒤 따로 실행합니다. `demo_move01`의 진단 로그는 그 옵션이 `false`였고, 일반 기록 중에는 관절/좌표 이동 목표를 보내지 않습니다. 해당 파일에서 J4는 시작 2.462도 → 최대 34.035도 → 끝 6.840도, J5는 시작 2.663도 → 최대 27.116도 → 끝 3.928도로 변했습니다. 돌아오는 모양이 기록됐다는 사실과 그 원인이 자동 복귀 명령이었다는 해석은 구분해야 합니다.

중력 보상 오차, 설치 방향 또는 도구 설정, 관절별 하중·마찰 차이 등은 원인 후보입니다. 현재 로그에는 손을 놓은 시각이나 실제 설치 설정, 보상 토크가 없으므로 특정 원인을 확정할 수 없습니다. J7이 멈춘다고 다른 관절의 손 유도도 정상이라고 판단하지 않습니다. 제조사는 Nero V112 손 유도에서 원치 않는 힘/방향으로 움직이는 사례에 대해 Web 제어기의 설치 방향 설정을 확인하도록 안내했습니다. 실제 장비는 책상 위 정방향 설치이므로 저장 설정도 이에 맞는지 확인해야 합니다. [제조사 안내](https://github.com/agilexrobotics/pyAgxArm/discussions/51).

손을 놓자 원래 자세로 뚜렷하게 끌려간다면 이를 정상 자동 복귀로 간주하고 더 세게 누르지 마세요. 설치·도구 설정을 확인한 뒤 작은 동작으로 거동을 확인하고 큰 경로의 실제 재생으로 진행합니다.

## 8. 중단과 복구

### MIT/CPV 상태에서 기록 진입이 막힌 경우

`교시 진입 전 이동 모드가 P/J/L/C가 아닙니다`는 교시 중단이 아니라 진입 전 거부입니다. `record`는 모터가 활성화된 상태에서 MIT/CPV를 임의로 위치 제어로 바꾸지 않습니다. `ctrl_mode=CAN_CTRL(1)`, `arm_status=NORMAL(0)`, 모터 모두 활성화여도 `mode_feedback=MOVE_MIT(6)`이면 이 조건에 걸립니다. `ctrl_mode=6`인 연동 교시 모드와 `mode_feedback=6`인 MIT 이동 종류를 혼동하지 마세요.

2026-11-12 13:28 실행 후 읽기 전용 실물 확인에서 CAN 제어·정상 상태·모터 7개 활성화와 함께 `MOVE_MIT(6)`이 확인됐습니다. 그 실행은 교시 요청이나 파일 생성을 하기 전에 끝났습니다. MIT로 바뀐 정확한 시점은 해당 기록 진입 로그만으로 확정할 수 없습니다.

팔과 도구를 받침 등으로 안전하게 지지하고 멈춘 뒤, 아래 명령을 **한 줄씩 성공 여부를 확인하며** 실행합니다. disable/enable에서 팔의 자세가 달라질 수 있으므로 지지 상태를 유지하세요.

```powershell
python nero_disable.py
python nero_teach.py prepare --execute
python nero_enable.py
python nero_read_status.py
```

`prepare`는 일반 CAN 상태, 모터 7개 비활성, 관절 제한과 오류 상태를 검사하고 0.5초 정지를 관찰한 뒤 모드 설정 패킷 하나로 MOVE_J·위치/속도 제어·속도 비율 5%를 요청합니다. 이동 목표, 모터 enable/disable, reset, 역할 전환은 보내지 않습니다. 모터가 하나라도 켜져 있으면 모드 설정도 보내지 않습니다. 단순히 `CAN_CTRL`만 돌아오는 것으로 완료하지 않고 새 `MOVE_J` 피드백과 모터 7개 비활성 유지까지 확인합니다. 이 준비 절차의 실제 모드 변경은 사용자 실행으로 확인해야 하며, 새 명령은 가상 CAN에서 검증했습니다.

위 명령 중 하나라도 실패하면 다음 줄로 진행하지 마세요. 최종 조회에서 `CAN_CTRL`, `NORMAL`, `MOVE_J`, 모터 7개 `True`가 확인되면 새 5초 기록을 시작합니다.


일반 CAN/MIT 상태에서 `record`를 바로 시작하는 제한은 유지합니다. 다만 **교시 종료 중 `ctrl_mode=6`과 `MOVE_MIT(6)`이 함께 관측되는 경우**는 아래 복귀 절차에서 처리합니다. 준비 후 기록 진입이 가능해지는 것과 실제 교시 종료 복귀까지 성공하는 것은 별도로 확인해야 합니다.

### 기록 또는 복귀 도중 중단한 경우

`Ctrl+C`는 중단입니다. record 도중 중단하면 가능한 경우 팔이 멈춘 것을 관찰한 뒤 제어 모드 복귀를 시도하지만, 파일은 중단 상태로 남기고 자동 재생을 거부합니다. 정상 기록은 정해진 시간과 정지 관찰을 끝까지 완료합니다. 제어 복귀 중 다시 중단하면 모드가 확인되지 않은 상태로 남을 수 있습니다.

모드 복귀가 확인되지 않았을 때는 팔과 도구를 지지하고 멈춘 뒤 다음 명령을 사용합니다.

```powershell
python nero_teach.py control --execute
```

이 명령은 leader 패킷이 있으면 해당 관절각으로, 없으면 새 일반 관절·상태·드라이버 피드백으로 정지를 관찰합니다. 전용 leader 패킷만 수신되는 경우에는 일반 피드백을 기다리기 전에 follower 역할을 요청합니다. 이후 보고 재개를 요청하고 새 일반 피드백, 자세 변화, 모터 상태를 검사한 뒤 CAN 제어권을 요청합니다. 교시 종료 시 `ctrl_mode=6 / MOVE_MIT(6)`이면 기록 시작 전 이동 모드로 복귀를 요청하며, 별도 `control` 실행은 MOVE_J를 선택합니다. 목표·enable·disable·reset은 보내지 않습니다. 마지막으로 `ctrl_mode=1`, 요청한 이동 모드, 기존 모터 상태가 유지되고 관절 변화가 허용 범위 내인지 0.2초 이상 및 새 관절 패킷 3세트 이상으로 확인합니다. 일반 CAN/MIT 상태나 다른 알 수 없는 모드에는 이 예외를 적용하지 않습니다. 통신이 끊겼거나 오류 상태면 복귀가 미확인 상태로 남을 수 있습니다.

모터가 7개 모두 꺼져 있고 `arm_status=JOINT_BRAKE_NOT_RELEASED(6)`인 경우에도 모드 복귀만 수행할 수 있습니다. 복귀 전 모터 상태를 관측할 수 있었다면 그 상태를 유지해야 성공으로 판정합니다. 일반 상태가 없는 leader 전용 복구에서는 follower 전환 뒤 처음 수신한 모터 상태를 검사하고 CAN 제어 요청 전후에 유지되는지 확인합니다. 일부만 활성화된 상태가 관측되면 중단합니다. `record`는 진입 전 모터 7개 활성화를 확인했으므로 종료 시에도 같은 상태를 요구합니다. `control` 성공은 모터 활성화나 손 유도 성공을 의미하지 않습니다.

**펌웨어 조회 자체도 무응답인 경우**, 이미 펌웨어 1.12임을 확인한 이 프로젝트 장비에서는 다음처럼 버전을 명시할 수 있습니다.

```powershell

```

이 경로는 펌웨어 조회 없이 지정한 드라이버로 연결합니다. 다른 버전의 장비에 추측으로 사용하지 않습니다. leader 관절각과 일반 관절각 어느 쪽도 완전하고 최신인 상태로 수신되지 않으면 역할 전환을 진행하지 않습니다. leader 관절각으로 정지를 확인하고 follower로 전환했더라도, 일반 관측이 돌아오지 않으면 이후의 유효한 CAN 제어 요청을 보내지 않습니다. 전원·USB-CAN 연결 여부도 확인해야 합니다.
