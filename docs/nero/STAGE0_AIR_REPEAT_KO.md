# 0단계: 공중 왕복과 위치·시간 기록

`nero_repeat_air.py`는 현재 위치를 A로 정하고 베이스 X/Y/Z 중 한 축으로 떨어진 B까지 갔다가 A로 돌아옵니다. 도구와 물체가 접촉하지 않는 공중 실험용입니다. 이번 단계에서는 소리나 힘을 기록하지 않습니다.

손으로 직접 움직여 가르친 경로를 재생하려면 별도 [수동 교시 도구](HAND_TEACH_KO.md)를 사용합니다.

## 1. 세 가지 모드

| 명령 옵션 | 수행하는 일 | 모터 활성화/이동 명령 |
| --- | --- | --- |
| 옵션 없음 또는 `--preview` | 현재 좌표와 A/B 경로 표시 | 보내지 않음 |
| `--record-only` | 현재 상태를 CSV에 기록 | 보내지 않음 |
| `--execute` | A → B → A 반복과 동시 기록 | 이동 명령 전송. 자동 enable은 하지 않음 |

기본값은 X방향 +5mm, 왕복 3회, 각 도착 후 1초 대기, 기록 목표 20Hz입니다. 실제 이동은 `--execute`를 명시해야 실행됩니다. 기본 미리보기에서는 파일도 생성하지 않습니다.

## 2. 처음 실행할 순서

프로젝트 루트 `RobotArm`에서 기존 `.venv` 환경을 사용합니다. 추가 Python 패키지는 필요하지 않습니다. 다른 로봇 제어/상태 조회 프로그램은 종료하고 한 프로그램씩 실행하세요.

### ① 상태 조회

```powershell
python nero_read_status.py
```

전원과 CAN 피드백 수신을 확인합니다. 기록 전용 모드는 모터가 비활성화되어 있어도 사용할 수 있습니다.

### ② 움직이지 않고 10초 기록

```powershell
python nero_repeat_air.py --record-only --duration 10
```

출력에 `기록 폴더`가 표시됩니다. 정상 수신 중이면 `유효` 행이 쌓이고 `무효`는 0이어야 합니다. 모터 비활성화 자체는 무효 피드백이 아닙니다. `feedback_valid`는 값과 수신 시각의 유효성을 나타내며, 모든 상태가 구동 가능하다는 의미는 아닙니다.

### ③ 경로 미리보기

```powershell
python nero_repeat_air.py --preview --axis x --mm 5 --cycles 1
```

예를 들어 현재 A가 `[100, -20, 400]`mm라면 B는 `[105, -20, 400]`mm입니다. 이 숫자는 설명용이며 명령에 고정 입력되지 않습니다. 실제 A는 실행 시 조회한 현재 위치입니다.

`--axis x --mm 5`는 **베이스 +X 방향으로 5mm**입니다. 도구가 향하는 방향과는 다릅니다. `--mm -5`는 반대 방향입니다. 좌표와 로봇 전체가 움직일 공간을 확인해 축과 부호를 선택하세요. 미리보기는 도달 가능성·충돌·접촉 여부를 판정하지 않습니다.

### ④ 모터 활성화 후 한 번 왕복

기존 방식으로 공중 이동 준비가 된 자세에서 진행합니다.

```powershell
python nero_enable.py
```

모터 7개 활성화 및 정상 CAN 제어를 확인한 다음 실행합니다.

```powershell
python nero_repeat_air.py --execute --axis x --mm 5 --cycles 1
```

**이 명령은 실제로 움직입니다.** 시작 위치에서 +X 5mm 이동하고, 도착을 확인한 뒤 시작 위치로 돌아옵니다. 모터는 종료 후 활성화 상태로 남습니다. 기존 자세를 변경해 실행하면 A/B도 새 자세를 기준으로 정해집니다.

### ⑤ 같은 경로를 3회, 이후 10회 반복

한 번 왕복이 정상적으로 끝났으면 같은 설정으로 횟수를 늘립니다.

```powershell
python nero_repeat_air.py --execute --axis x --mm 5 --cycles 3
```

```powershell
python nero_repeat_air.py --execute --axis x --mm 5 --cycles 10
```

한 실행 안에서는 A/B를 처음 한 번만 정하고 계속 재사용합니다. 상대 이동 오차를 더해 다음 목표를 만드는 방식이 아닙니다. 실행 간에도 완전히 같은 절대 경로를 비교하려면 A/B 기록을 확인해야 합니다.

## 3. 옵션과 제한

| 옵션 | 기본값 | 의미 |
| --- | --- | --- |
| `--axis` | `x` | 베이스 기준 축: x/y/z |
| `--mm` | `5` | 부호 있는 편도 거리. 절댓값 1~20mm |
| `--cycles` | `3` | 왕복 횟수. 1~100 |
| `--pause` | `1` | 각 도착 후 대기 시간(초) |
| `--timeout` | `30` | 각 편도 이동의 완료 대기 시간(초) |
| `--duration` | `10` | 기록 전용 모드의 수집 시간(초) |
| `--sample-hz` | `20` | 기록 폴링 목표 빈도. 5~50Hz |
| `--output-dir` | `data/nero_air` | 실험별 하위 폴더를 생성할 위치 |
| `--channel` | `0` | Windows USB-CAN 채널 |

속도 비율은 기존 예제와 같은 5%로 고정했습니다. 5mm/s가 아닙니다. 이 0단계 스크립트는 큰 거리·고속 실험보다 반복 기록 확인을 목적으로 편도 20mm까지만 허용합니다.

## 4. 저장 파일

매번 날짜·시각과 임의 ID를 붙인 새 폴더를 생성하므로 이전 실험을 덮어쓰지 않습니다.

```text
data/nero_air/20261111_153000_a1b2c3d4/
  meta.json       # 실행 설정, 펌웨어, A/B 좌표, 단위
  robot.csv       # 시간별 관절각·위치·상태·원시 수신 시각
  events.jsonl    # 단계 전환, 편도 이동 요청/완료, 종료 이유
  summary.json    # 완료/중단 여부, 행 수, 각 도착 결과
```

기본 출력 경로 `data/nero_air/`는 `.gitignore`에 추가했습니다. 다른 출력 경로를 직접 지정하면 해당 경로의 Git 제외 여부도 확인하세요.

CSV는 Excel에서 열 수 있도록 UTF-8 BOM으로 저장합니다. 먼저 다음 열을 보세요.

| 열 | 의미 |
| --- | --- |
| `elapsed_s` | 기록 시작 후 단조 증가 시계 기준 경과 시간 |
| `host_epoch_s` | PC의 epoch 시각. CAN 시각과 비교할 때 사용 |
| `cycle` / `phase` | 왕복 번호 / baseline·outbound·hold_b·return·hold_a 등 |
| `x_mm`, `y_mm`, `z_mm` | 로봇 피드백 기준 플랜지 위치 |
| `target_x_mm` 등 | 해당 구간의 목표 위치 |
| `j1_deg` ~ `j7_deg` | 관절각(도) |
| `j1_enabled` ~ `j7_enabled` | 모터 활성화 여부 |
| `feedback_valid` / `error` | 수신값·시각 유효 여부 / 무효 이유 |
| `pose_is_new` / `joint_is_new` | 이전 샘플 대비 새 수신 시각인지 여부 |
| `pose_epoch_s` 등 | 통합값과 개별 CAN 메시지의 원시 수신 시각 |
| `estimated_speed_mm_s` | 새 플랜지 피드백 간 위치 차이/수신 시각 차이로 계산한 추정 속도 |

`estimated_speed_mm_s`가 비어 있으면 처음 샘플이거나 같은 피드백을 다시 읽은 경우 등입니다. 빈칸을 0으로 해석하지 않습니다.

## 5. 결과를 보는 방법

먼저 `summary.json`의 `status`가 `completed`인지, 무효 행이 0인지, 완료한 편도 구간 수가 `왕복 횟수 × 2`인지 확인합니다. `completed`여도 기록 전용 모드에서는 무효 행이 있을 수 있으므로 행 수도 함께 봅니다.

위치 오차를 측정한 완료 구간이 없으면 `max_endpoint_error_mm`는 `null`입니다. 오차가 0이라는 뜻이 아닙니다.

그다음 CSV를 Excel에서 열어 `elapsed_s`를 가로축, 선택한 축의 위치(예: `x_mm`)를 세로축으로 선 그래프를 만드세요. A와 B 사이의 움직임과 양끝 대기 구간이 반복되어야 합니다. `phase`로 왕복 방향을 나눌 수 있습니다. 이 단계의 `outbound`와 `return`에는 이동 전 약 0.5초 관절 관찰도 포함됩니다.

`summary.json`에는 각 편도 도착 위치와 목표 오차가 저장됩니다. 같은 방향의 도착 결과가 비슷한지 확인하세요. 이 값은 **로봇 자체 피드백과 목표의 차이**이며, 외부 계측기로 측정한 절대 정확도나 제조사 반복 정밀도 시험 결과는 아닙니다. 같은 XYZ/RPY로 돌아와도 7개 관절 자세가 완전히 같다는 보장은 없습니다.

기록 빈도는 OS 스케줄링에 따라 달라집니다. CSV 행 수가 새로운 CAN 메시지 수와 같지는 않습니다. 여러 CAN 메시지에서 조립한 위치/관절값은 완전한 동시 측정값이 아니므로 속도에는 노이즈가 포함됩니다. 펌웨어 1.12의 0으로 처리되는 모터 속도 필드를 사용한 값은 아닙니다.

## 6. 중단 시 동작

- 이동 전에 모터 활성화, 정상 CAN 제어, 드라이버 오류, 관절 변화와 최신 피드백을 기존 코드로 확인합니다.
- 실제 왕복에서는 기록 스레드도 수신 상태를 확인합니다. 기록 실패나 샘플 중단을 발견하면 다음 명령을 막고, 이동 중이면 기존 이동 함수가 전자 급정지를 요청합니다.
- `Ctrl+C`, 시간 초과, 피드백 오류로 이동이 중단되면 자동 복귀·재시도·reset을 하지 않습니다. 남은 경로도 실행하지 않습니다.
- 그때까지 저장한 CSV와 이벤트, 중단 상태를 보존합니다. 디스크가 가득 찼거나 쓰기 권한이 없는 등 저장 장치 자체의 문제에서는 일부 파일이 완성되지 않을 수 있습니다.
- 전자 급정지는 실제 정지를 보장하는 하드웨어 안전 기능이 아닙니다. 급정지 후에는 상태를 조회하고 원인을 확인하세요. reset/disable 시 팔이 처질 수 있으므로 기존 지지 절차를 따릅니다.

정상 종료 후 실습을 마치고 모터를 비활성화할 때는 기존 `python nero_disable.py`를 사용합니다. 이 프로그램이 자동으로 disable하지는 않습니다.

## 7. 0단계 완료 기준

1. 움직이지 않는 상태에서 10초 기록을 정상 저장한다.
2. 미리보기로 실제 현재 위치와 경로를 이해한다.
3. 짧은 공중 왕복 1회가 정상 종료한다.
4. 3~10회 반복 기록에서 누락과 중단 여부, 도착 결과를 설명할 수 있다.
5. 위치/시간 그래프를 보고 접근·이동·대기 구간을 구별할 수 있다.

이후 녹음 장비가 준비되면 같은 동작의 모터 소음과 배경 소음을 함께 수집하고, 팁·지그·힘 센서를 준비한 뒤 1단계 접촉 실험으로 넘어갑니다.
