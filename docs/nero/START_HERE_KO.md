# Nero 처음 사용하기 — 현재 프로젝트 기준

좌표 이동을 익힌 뒤 긁기·소리 수집·학습 실험을 진행하려면 [긁기 소리 연구 단계별 계획](SCRATCH_AUDIO_RESEARCH_PLAN_KO.md)을 참고하세요.

이 문서는 로컬 pyAgxArm 코드와 2026-11-09 실제 장비의 상태 조회를 바탕으로 작성했습니다. 실제 이동, 모터 활성화, 캘리브레이션, 설정 변경은 실행하지 않았습니다. 아래 상태는 조회 시점의 값입니다.

초기 조회 후 사용자가 전원/연결을 변경하면서 응답이 없었지만, 전원을 다시 연결한 뒤 펌웨어와 관절 상태 수신을 재확인했습니다. 아래 표는 재연결 후 조회 결과입니다. 0.3초 간격의 세 표본에서 관절 수신 시각이 계속 증가했고, 표본의 수신 지연은 약 6~11ms였습니다. 조회 스크립트는 가상 CAN에서도 펌웨어 자동 선택과 상태 수신을 검증했으며, 송신 프레임이 펌웨어 조회뿐인 것도 확인했습니다.

## 1. 지금 연결된 장비에서 확인한 것

| 항목 | 조회 결과 | 의미 |
| --- | --- | --- |
| PC 연결 | Windows, `agx_cando`, 채널 `"0"` | USB-CAN을 통한 상태 조회 성공 |
| 펌웨어 | `1.12` | SDK에서는 `NeroFW.V112` 사용 |
| 제어 모드 | `ETHERNET_CONTROL_MODE` | 조회 당시 Ethernet 제어 모드. CAN으로 데이터가 보이는 것과 CAN 제어권을 갖는 것은 다름 |
| 로봇 상태 | `JOINT_BRAKE_NOT_RELEASED` | 브레이크 미해제 상태 보고 |
| 모터 활성화 | 7개 모두 `False` | 아직 모터를 활성화하지 않은 상태 |
| 관절 오류 비트 | 각 관절의 각도 제한/통신 오류가 모두 `False` | 이 오류 비트들에는 이상이 보고되지 않음. 전체 구동 준비가 끝났다는 의미는 아님 |
| 드라이버 오류 비트 | 저전압·과열·과전류·충돌·드라이버 오류·스톨 모두 `False` | 해당 피드백에는 이상 보고 없음 |
| 전압·온도 피드백 | 전압 `23.2~23.7V`, 드라이버 `26~27°C`, 모터 `20~22°C` | 조회 시점 값. 부하를 걸었을 때의 검증은 하지 않음 |
| 그리퍼 | AGX 그리퍼 형식의 피드백 수신, width 모드, 비활성화 | 그리퍼 제어를 별도로 시도할 수 있음. 장착 모델과 실제 최대 벌림 폭 확인 필요 |
| J2 각도 | 약 `-100.557°` | SDK 기본 하한 `-100°`보다 약 `0.557°` 작음 |
| J4 각도 | 약 `125.768°` | SDK 기본 상한 `123°`보다 약 `2.768°` 큼 |

**7개 관절 모두 컨트롤러 내부 제한값 조회는 응답을 얻지 못했습니다.** 따라서 SDK 프리셋과 실기기 제한이 왜 다른지, 영점이나 하드웨어에 문제가 있는지는 이 조회만으로 판단할 수 없습니다. 로봇이 보고한 각도 제한 오류 비트는 모두 `False`이고, SDK 프리셋 범위 밖이라는 검사는 PC 측에서 별도로 계산한 것입니다.

중요한 코드 동작: `move_j()`는 7개 관절 목표를 모두 받으며, 기본 설정에서는 범위를 벗어난 목표를 SDK 제한 안으로 보정합니다. 현재 자세를 복사해 J7만 바꿔도 J2와 J4 목표가 함께 보정될 수 있습니다. 먼저 제조사 제어 화면/절차에서 현재 자세와 제한을 확인하고, 범위 안의 시험 자세를 확보하세요. 범위를 임의로 넓히거나 영점을 다시 설정해서 해결하지 마세요.

재조회 당시 `motion_status`는 `1`(목표 도달 안 됨)이었습니다. 이 값 하나로 새 고장을 판정할 수 없으며 브레이크/활성화 상태와 함께 봐야 합니다. 또한 펌웨어 1.12용 SDK는 `get_motor_states().msg.velocity`를 0으로 덮어쓰므로, 이 속도값으로 정지를 검증하면 안 됩니다.

## 2. 이 프로젝트는 무엇인가?

Python 프로그램에서 관절 각도와 손끝 위치를 지정해 Nero를 제어하는 SDK입니다. 이 저장소 자체가 카메라 인식이나 자동 집기까지 제공하는 완성 앱은 아닙니다.

```text
내 Python 코드
  → create_agx_arm_config / AgxArmFactory: 기종·펌웨어·연결 설정
  → Nero 드라이버: 이동/조회 함수를 CAN 메시지로 변환
  → python-can + agx_cando: Windows USB-CAN 통신
  → 로봇 컨트롤러: 명령 실행 및 상태 회신
```

| 파일/폴더 | 역할 | 처음에 볼 필요 |
| --- | --- | --- |
| `nero_read_status.py` | 이번에 추가한 모터를 활성화하지 않는 상태 조회 예제 | 먼저 실행 |
| `nero_enable.py` | 2단계: 이동 목표 없이 모터 활성화와 CAN 제어 확인 | 상태 조회 다음에 실행 |
| `nero_disable.py` | 정지 상태에서 모터 7개 비활성화 확인 | 실습 종료 시 사용 |
| `nero_reset.py` | 기본은 상태 조회, `--execute`일 때만 급정지 복구 1회 요청 | 급정지 원인과 팔 지지를 확인한 후 사용 |
| `nero_move_joint.py` | 3단계: 활성화된 관절 하나를 상대 각도로 조금 이동 | 첫 실제 이동 |
| `nero_move_linear.py` | 4단계: 방향을 유지하며 플랜지를 베이스 X/Y/Z 방향으로 1~5mm 직선 이동 | 관절 이동 다음 실습 |
| `nero_move_to.py` | 현재 좌표 조회 후 목적지의 절대 X/Y/Z(mm)를 입력해 직선 이동 | 좌표로 목적지를 지정할 때 |
| `pyAgxArm/demos/nero/test1.py` | Nero API 호출 예제 모음 | 사용법 참고 |
| `docs/nero/nero_api.md` | Nero 전체 API, 단위, 반환값 | 함수가 궁금할 때 |
| `pyAgxArm/api/agx_arm_factory.py` | 설정 생성, 펌웨어별 드라이버 선택 | 구조 이해용 |
| `pyAgxArm/api/constants.py` | 기종별 관절 이름과 SDK 기본 제한 | 제한 확인용 |
| `pyAgxArm/protocols/can_protocol/drivers/nero/` | Nero 제어 구현 | 처음에는 수정 불필요 |
| `…/nero/versions/v112/driver.py` | 1.12용 제어권/활성화, CPV, IK 피드백 등의 차이 | 현재 장비의 버전별 동작 |
| `…/nero/default/parser.py`, `…/msgs/nero/` | CAN 데이터 해석, 패킷 형식 | 처음에는 수정 불필요 |
| `…/drivers/effector/agx_gripper/` | 그리퍼 제어 구현 | 그리퍼를 쓸 때 |
| `tests/` | 가상 CAN으로 명령/피드백 등을 검증 | 실물 충돌 여부를 검증하는 시뮬레이터는 아님 |

Nero 버전 드라이버는 `default → v111 → v112 → v120 → v121`로 이전 구현을 상속하고 바뀐 동작을 덮어씁니다. 따라서 1.12에서 사용하는 `move_j()` 등은 `default/driver.py`에 있고, Cartesian 좌표 처리는 `v111` 구현을 상속합니다. 파일 이름의 `default`가 현재 장비의 권장 설정이라는 뜻은 아닙니다.

## 3. 첫 단계: 움직이지 않고 확인하기

현재 `.venv`에는 Python 3.12.9, python-can 4.6.1과 Windows용 `agx_cando`가 있습니다. 재설치부터 할 필요는 없습니다.

프로젝트 폴더의 PowerShell에서:

```powershell
cd C:\Users\user\Desktop\RobotArm
.\.venv\Scripts\python.exe .\nero_read_status.py
```

계속 보려면:

```powershell
.\.venv\Scripts\python.exe .\nero_read_status.py --watch
```

이 스크립트는 펌웨어를 조회해 맞는 드라이버로 다시 연결하고, 관절 각도·모터 활성화 상태·로봇 상태·플랜지 위치를 출력합니다. `enable()`, `move_*()`, 캘리브레이션은 호출하지 않습니다. `Ctrl+C`는 이 조회 프로그램을 종료합니다. 로봇의 물리 정지 기능을 대신하지 않습니다.

출력에서 확인할 것:

- `None`: 아직 해당 데이터를 못 받았다는 뜻입니다. 각도가 0이라는 뜻이 아닙니다.
- 관절 각도는 SDK에서 **라디안(rad)**을 사용합니다. 스크립트는 **도(deg)**도 함께 표시합니다. 2°는 약 0.0349rad이고, 90°는 약 1.5708rad입니다.
- `.msg`가 실제 데이터이고 `.timestamp`는 수신 시각, `.hz`는 SDK가 측정한 메시지 수신 빈도입니다.
- 모터 활성화 여부는 피드백입니다. 데이터가 없거나 오래됐다면 현재 상태라고 단정하지 마세요.
- `connect()` 성공은 PC의 통신 연결 성공입니다. 로봇 구동 준비 완료 여부는 상태/제어 모드/모터 활성화도 함께 확인해야 합니다.

### 상태 조회 다음: 모터 활성화만 확인하기 (2단계)

사용자가 보내 준 후속 화면에서는 7개 관절이 모두 SDK 기본 범위 안에 있었습니다. 자세는 이후 바뀔 수 있으므로 `nero_enable.py`가 실행 직전에 다시 확인합니다. 이 파일도 입문 실습용으로 새로 추가한 파일입니다.

팔과 도구 주변을 비우고 베이스 고정 및 비상정지 절차를 확인한 뒤, 다른 제어 프로그램이 동작 명령을 보내지 않는 상태에서 실행하세요. 활성화는 브레이크와 지지 상태를 바꾸므로 자세가 달라질 수 있습니다.

```powershell
.\.venv\Scripts\python.exe .\nero_enable.py
```

이 프로그램은 최근 피드백·현재 각도·드라이버 오류를 확인하고, 제한 시간 내 `enable()`을 호출해 모터 7개 활성화, CAN 제어 모드, 정상 상태를 확인합니다. 이동 목표, 영점 설정, 오류 reset은 보내지 않습니다. 실패 또는 실행 중 Ctrl+C가 발생하면 활성화를 시도한 경우에 한해 전자 급정지 명령을 요청합니다. 통신 단절 시에는 전자 급정지도 전달되지 않을 수 있습니다.

성공 시 `모터 활성화 피드백`이 모두 `True`, `ctrl_mode`가 CAN 제어, `arm_status`가 정상으로 표시되고 종료됩니다. **프로그램 종료는 비활성화가 아닙니다. 성공 후 모터는 활성화 상태로 남습니다.** 결과를 확인한 뒤 다음 실습으로 넘어갑니다. 이 파일은 가상 CAN에서 검증하며 실제 장비에서는 사용자가 실행합니다.

`2단계 중단: 목표 도달 상태가 아닙니다`가 표시된 경우, 이전 버전의 입문 예제는 활성화 명령을 보내기 전에 중단한 것입니다.

`CAN_CTRL`은 제어 모드이고, 모터 활성화 여부는 별도로 확인해야 합니다. **모터 7개 모두 `False` + `JOINT_BRAKE_NOT_RELEASED(6)` + `motion_status=1`** 조합은 수정한 활성화 예제에서 허용합니다. 이미 모터 7개가 활성화된 정상 CAN 제어 상태라면 목표 미도달 표시만으로 오류를 내지 않고, 추가 enable 요청 없이 상태를 출력합니다. 각도 제한, 최근 피드백과 드라이버 오류 검사는 유지합니다. 일부만 활성화된 상태의 예외 처리는 추가하지 않았습니다.

비활성화 중의 `motion_status=1`은 컨트롤러가 목표 미도달을 보고한다는 뜻입니다. 그 이유나 이전 목표가 남아 있는지는 이 값만으로 확정할 수 없습니다. 수정한 예제도 목표를 지우거나 현재 자세 유지 명령을 보내지 않으며, reset을 자동 실행하지 않습니다. 활성화로 브레이크/지지 상태가 달라질 수 있으므로 주변 공간을 확보하세요. 활성화 성공 후 목표 미도달 표시가 남더라도 아래 이동 전 관찰 검사를 통과하면 새 목표를 보낼 수 있습니다.

### 이동 전에 목표 도달 상태(0)를 요구하던 문제 수정

예전 이동 예제는 `check_before_enable()`을 재사용해 `motion_status != 0`이면 `robot.move_l()`/`move_j()`를 호출하기 전에 중단했습니다. 따라서 `python nero_move_linear.py --axis z --mm -4`가 중단된 원인은 로봇의 -4mm 목표 거절이 아니라 이 PC 측 조건이었습니다. 제조사 SDK의 `move_l()` 자체에는 명령 전 `motion_status=0`을 요구하는 조건이 없습니다.

현재 예제는 활성화 검사와 이동 전 검사를 구분합니다. `check_before_move()`는 먼저 **관절·로봇 상태·7개 드라이버의 필요한 피드백 전체를 최대 2초 기다린 뒤**, 0.5초 동안 새 관절 피드백을 관찰합니다. 7개 모터 활성화·정상 CAN 제어·오류 비트·관절 범위를 검사합니다. 관찰 구간에서 어느 관절이든 각도 범위가 0.05도를 넘으면 새 목표를 보내지 않습니다. 수신 시각이 갱신된 관절 표본이 최소 3개 있어야 하며, 알 수 없는 `motion_status` 값은 거부합니다. **이전 목표의 `motion_status=1`만으로는 차단하지 않습니다.**

이것은 소프트웨어 피드백 관찰이며 매우 느린 움직임, 관찰 종료 후의 외부 명령, 장애물이나 자기 충돌까지 배제하는 안전 기능은 아닙니다. 특히 펌웨어 1.12에서는 SDK 모터 속도값이 0으로 보정되므로 그 값을 정지 판정에 사용하지 않습니다. 관절 피드백은 여러 CAN 프레임의 집계값이라는 한계도 있습니다. 다른 제어 프로그램이 명령을 보내지 않는 상태에서 사용하세요.

이동을 요청하면 `move_l CAN 명령 전송 완료` 또는 `move_j CAN 명령 전송 완료`를 출력합니다. 이는 PC의 전송 완료이며 로봇 수락/도착 확인과 다릅니다. 명령을 보낸 다음에는 기존대로 목표 도달 상태(0)와 실제 목표 오차를 함께 확인합니다. 시간이 초과되면 현재 `motion_status`, 위치/각도 오차 등을 출력하고 전자 급정지를 요청합니다. 예를 들어 위치 오차는 0에 가까운데 `motion_status=1`이면, 좌표가 변하지 않은 경우와 구분해 추가 진단할 수 있습니다.

2026-11-10 실물에는 이동 명령을 보내지 않고 새 이동 전 관찰 검사만 실행했습니다. 해당 시점에 검사를 통과했고, 현재 `(-23.617, -14.707, 716.275)mm`에서 Z -4mm의 계산된 목표는 `(-23.617, -14.707, 712.275)mm`였습니다. 이는 계산/관찰 결과이며 실물에서 해당 경로의 도달 가능성을 확인한 것은 아닙니다. 실제 -4mm 전송과 도착 검증은 가상 CAN 회귀 테스트에서 수행했습니다.

### 모터는 True인데 EMERGENCY_STOP인 경우

`arm_status=EMERGENCY_STOP(1)`과 모터 비활성화는 다른 상태입니다. 실제 조회에서 모터 7개가 모두 `True`인데 급정지 상태가 유지되는 경우가 확인됐습니다. 이 상태에서 `nero_enable.py`는 활성화 요청을 보내기 전에 중단합니다. `enable()`로 급정지를 해제하는 것은 아닙니다.

이동 전 검사에서 이미 `EMERGENCY_STOP`을 보고 중단한 실행은 새 이동 명령이나 전자 급정지를 보내지 않습니다. 반면 이동 전송 단계가 시작된 후 오류, 피드백 지연, 시간 초과 또는 Ctrl+C가 발생하면 예제는 전자 급정지를 요청합니다. 이후에는 `급정지 요청 원인`도 출력합니다. 급정지를 처음 일으킨 조건은 직전 실행 로그로 확인해야 하며, 현재 상태 피드백만으로 확정할 수 없습니다.

**제조사 API 문서는 `reset()` 시 모터가 비활성화되고 팔이 즉시 처질 수 있다고 경고합니다. 팔과 도구가 안전하게 지지된 상태에서만 복구 요청을 실행하세요.** 원점 복귀나 영점 설정 명령이 아니며 이전 목표 제거를 보장하는 기능으로 가정하면 안 됩니다. 제조사 문서는 급정지 이후 모터가 활성화된 상태에서 reset이 유효하다고 설명합니다.

먼저 조회만 하려면:

```powershell
.\.venv\Scripts\python.exe .\nero_reset.py
```

급정지 원인과 지지 상태를 확인한 뒤 실제 복구를 1회 요청하려면:

```powershell
.\.venv\Scripts\python.exe .\nero_reset.py --execute
```

이 파일은 최근 피드백, CAN 제어, 급정지 상태, 모든 모터 활성화, 드라이버 오류, 현재 관절 범위와 0.5초 관절 변화를 확인한 후 `reset()`만 한 번 보냅니다. 자동 enable·이동·재시도는 하지 않습니다. 새 피드백에서 급정지가 해제됐는지 최대 3초 확인합니다. 상태가 정상(0) 또는 브레이크 미해제(6)로 바뀌면 결과와 모터 활성화 상태를 출력합니다. 해제되지 않으면 반복 요청하지 말고 원인 및 제조사 복구 절차를 확인하세요.

복구 후 모터가 비활성화됐다면 지지/주변 상태를 유지하며 `nero_enable.py`로 활성화 상태를 다시 확인합니다. 급정지에서 벗어나지 않은 상태에서 enable이나 이동을 반복하지 마세요. 이 파일의 복구 명령 검증은 가상 CAN으로만 수행했으며 실물에는 진단/조회만 실행합니다.

### 비활성화하려면

정지해 있는 팔/도구의 지지 상태를 확인한 후 실행합니다. 비활성화하면 팔이 처질 수 있습니다. 이동 중 급정지 버튼으로 사용하는 명령은 아닙니다.

```powershell
.\.venv\Scripts\python.exe .\nero_disable.py
```

핵심 SDK 함수는 `robot.disable()`입니다. 이 파일은 최근 상태 피드백과 목표 도달 상태를 확인하고 비활성화한 뒤, 7개 관절의 활성화 피드백이 모두 `False`인지 확인합니다. 제한/영점/이동 목표를 바꾸지 않습니다. `disconnect()`는 PC 연결 종료이고 `disable()`은 모터 비활성화입니다.

### 첫 실제 이동: J7을 현재보다 +2도 (3단계)

사용자가 보내 준 실행 화면에서 활성화 7개 모두 `True`, `ctrl_mode: CAN_CTRL(0x1)`, `arm_status: NORMAL(0x0)`이 확인됐습니다. 이 상태에서 다음 명령을 실행하면 J7의 목표 각도만 현재보다 2도 커집니다. 팔과 도구가 움직일 공간을 확보하세요.

```powershell
.\.venv\Scripts\python.exe .\nero_move_joint.py --joint 7 --degrees 2
```

이미 disable했다면 먼저 `nero_enable.py`를 실행해야 합니다. 이동 파일은 모터를 자동 활성화하지 않습니다. 현재 자세와 목표를 검사하고 `set_speed_percent(5)` → `move_j(target)` 순서로 한 번 전송합니다. 5%는 속도 비율이며 5도/초를 뜻하지 않습니다. 목표 도달 상태와 7개 관절의 목표 오차(각각 0.2도 미만)를 확인한 뒤 끝납니다. 성공 후 자동 복귀/비활성화는 하지 않으며 설정한 속도 비율은 5%로 남습니다.

이 스크립트는 현재 자세를 기준으로 실행할 때마다 목표를 새로 계산합니다. **같은 +2도 명령을 두 번 실행하면 총 약 +4도가 됩니다.** +2도 이동을 확인한 뒤 다음 명령은 현재보다 -2도 움직입니다. 사이에 다른 동작이 없었다면 시작 각도 부근으로 돌아갑니다.

```powershell
.\.venv\Scripts\python.exe .\nero_move_joint.py --joint 7 --degrees -2
```

`--joint`는 1~7번 관절, `--degrees`는 현재 각도에 더할 도수입니다. 입문 파일에서는 한 번에 절댓값 0.5~5도만 허용하며 SDK의 관절 제한도 검사합니다. 이동 중 오류/최근 피드백 소실/시간 초과/Ctrl+C에는 전자 급정지를 요청합니다. 전자 급정지는 통신에 의존하며, 급정지 이후에는 원인을 확인하고 제조사 복구 절차를 따라야 합니다. 이 파일은 reset을 자동 실행하지 않습니다.

관절 회전은 손끝을 X/Y/Z로 특정 거리만큼 옮기는 명령과 다릅니다. 직선 위치 이동은 이후 `move_l()` 단계에서 익힙니다. 작은 관절 각도도 주변 물체와의 충돌을 막아주지는 않습니다. 스크립트 검증은 가상 CAN에서 수행했으며 실제 구동은 사용자가 실행합니다.

### 다음 실습: 플랜지를 위로 5mm 직선 이동 (4단계)

`move_j()`는 관절 각도, `move_l()`은 플랜지 위치와 방향을 지정합니다. 방향을 유지하며 목표까지 직선으로 이동하려면 여러 관절이 함께 회전할 수 있습니다. 이 실습의 위치 기준은 도구 장착면인 플랜지이며, 그리퍼 끝은 아닙니다.

먼저 상태를 조회하고, 비활성화 상태라면 앞의 활성화 단계를 실행합니다. 팔과 도구의 이동 공간을 비운 뒤 다음 명령을 한 번 실행하세요. 도구가 물체에 닿아 있거나 물건을 잡고 있는 상태에서는 시작하지 마세요.

```powershell
.\.venv\Scripts\python.exe .\nero_move_linear.py --axis z --mm 5
```

현재 플랜지 위치를 읽고 **베이스 좌표계의 Z값에 0.005m를 더한 위치**를 목표로 보냅니다. 베이스가 수평으로 설치된 경우 위로 5mm 이동에 해당합니다. 도구 자체가 향한 방향을 기준으로 5mm 이동하는 명령과 다릅니다. 현재 방향(roll/pitch/yaw)은 목표에서 유지합니다. 모터를 자동 활성화하지 않으며, 속도 비율 5%에서 한 번 이동한 뒤 도착을 확인하고 종료합니다.

도착은 로봇의 목표 도달 상태, 위치 오차 0.5mm 미만, 방향 오차 1도 미만을 함께 검사합니다. 새 플랜지 수신 시각을 가진 표본에서 3회 확인합니다. 이것은 SDK 피드백을 통한 확인이며 외부 측정으로 정확도를 검증하는 것은 아닙니다. SDK의 플랜지 피드백은 여러 CAN 프레임을 합친 값이라 완전한 동시 수신을 보증하지 않습니다.

동작 성공을 확인하고 사이에 다른 이동이 없었다면 다음 명령으로 시작 위치 부근에 돌아올 수 있습니다. 직선 도착 가능 여부는 복귀 때도 검사되므로 자동 왕복시키지 않습니다.

```powershell
.\.venv\Scripts\python.exe .\nero_move_linear.py --axis z --mm -5
```

`--axis`는 베이스 기준 x/y/z, `--mm`는 현재 위치에 더할 mm입니다. 같은 +5mm 명령을 두 번 실행하면 총 약 +10mm가 됩니다. 이 파일은 한 번에 절댓값 1~5mm만 허용합니다. 작은 이동도 시작 자세나 도달 범위에 따라 해가 없거나 특이점 오류가 생길 수 있습니다. 이 SDK의 IK 피드백은 이동 후 조회 기능이며, 이 예제는 이동 전에 경로의 도달 가능성이나 충돌을 계산하지 않습니다. 오류가 나면 다음 목표를 계속 보내거나 자동 reset하지 말고 출력 결과를 확인하세요.

성공 후 모터는 활성화 상태이며 자동 복귀/비활성화는 하지 않습니다. 실행 중 오류·피드백 지연·시간 초과·Ctrl+C에는 전자 급정지를 요청합니다. 통신이 끊기면 요청도 전달되지 않을 수 있습니다. 검증은 가상 CAN으로 수행했으며, 실물 이동은 사용자가 실행합니다. 2026-11-10 예제 준비 중 상태 재조회에서는 채널 0을 열지 못했으므로 그 시점의 장비 자세는 새로 확인하지 못했습니다.

### 목적지 좌표를 직접 입력하기

`nero_move_to.py`는 로봇 베이스 기준의 **절대 X/Y/Z 좌표**를 입력받습니다. 프로그램에 입력하는 위치 단위는 **mm**이며, 내부에서 SDK 단위인 m로 변환합니다. 현재 방향은 이동 직전 피드백에서 읽어 유지하고 `move_l()`로 목표까지 직선 이동합니다. 현재 위치와 목적지 좌표의 차이는 프로그램에서 계산하므로, 관절 각도를 직접 계산할 필요는 없습니다.

먼저 움직이지 않고 현재 좌표만 확인하려면:

```powershell
.\.venv\Scripts\python.exe .\nero_move_to.py --preview
```

현재 위치를 확인하고, 모터가 활성화된 정상 CAN 제어 상태에서 입력식으로 이동하려면:

```powershell
.\.venv\Scripts\python.exe .\nero_move_to.py
```

프로그램은 현재 XYZ를 표시한 뒤 조회 연결을 닫고 목표 X, Y, Z를 차례로 묻습니다. 연결 종료는 모터 비활성화가 아니므로 모터의 활성화 상태는 유지됩니다. 각 항목에 숫자를 입력하며, Enter만 누르면 처음에 표시된 해당 좌표를 유지합니다. **세 항목 입력을 마치면 다시 연결해 최신 피드백을 받은 뒤 검사를 거쳐 실제 이동을 실행합니다.** 예를 들어 현재가 `(100, 200, 300)mm`일 때 X/Y는 Enter로 유지하고 Z에 `305`를 입력하면 목표는 `(100, 200, 305)mm`입니다. 이 숫자는 학습용 예시이며 실물의 현재 좌표로 가정하면 안 됩니다.

명령행에 목적지를 직접 적을 수도 있습니다. 다음은 **가상 예시 좌표의 미리보기**입니다. 실제 장비에서 실행할 좌표는 현재 위치와 작업 공간을 보고 정하세요.

```powershell
.\.venv\Scripts\python.exe .\nero_move_to.py --x 103 --y -198 --z 405 --preview
```

`--preview`를 빼면 실제 이동을 실행합니다. 생략한 축은 최초 표시된 현재 좌표를 유지합니다. 예를 들어 `--z 405`는 Z=405mm라는 절대 목표이고, 현재보다 405mm 올리는 명령이 아닙니다. 같은 절대 목표를 재실행하면 그 지점을 다시 목표로 하며, 상대 이동 예제처럼 이동량이 누적되지 않습니다.

단위·원점 입력 실수를 줄이기 위해 새 파일에는 기본적으로 **현재 위치에서 목표까지 직선 거리 20mm** 한도를 두었습니다. 이 한도는 입문 프로그램의 설정이고 Nero의 작업 반경이나 충돌 방지 기능이 아닙니다. 다른 범위를 의도할 때는 `--max-distance-mm`로 양수 mm 값을 명시할 수 있습니다. 크게 설정한다고 목표/경로가 도달 가능하거나 주변 공간이 확보되는 것은 아닙니다. 도착 확인 시간은 10초이며 장거리 이동은 그 안에 끝나지 않을 수도 있습니다.

프로그램은 자동 활성화·복귀·비활성화·reset을 하지 않습니다. 목표가 현재에서 0.5mm 미만이면 이동 명령 없이 종료합니다. 성공 후에도 모터는 활성화 상태입니다. 입력 중 시간이 지나면 이동 직전 좌표를 다시 읽어 거리 한도와 유지할 방향을 새로 확인합니다. 모터/오류/도착 피드백 검사와 실패 시 전자 급정지 요청은 기존 직선 이동 예제와 같은 함수를 사용합니다.

입력 후 `최근 플랜지 위치/자세 피드백이 없습니다`로 중단된 로그는 **이동 전송 전에 마지막 수신 데이터가 0.5초 이내라는 검사를 통과하지 못했다**는 뜻입니다. 좌표 계산이나 로봇의 목표 수락/거절 결과가 아닙니다. 수정한 입력 모드는 입력 중 수신 세션을 유지하지 않고 입력 완료 후 다시 연결합니다. 새 수신 시각을 가진 피드백을 최대 2초 기다리며, 피드백 자체의 0.5초 최신성 기준은 완화하지 않습니다. 최신 데이터가 오지 않으면 마지막 수신 경과 시간과 수신 스레드 상태를 표시하고 이동하지 않습니다. 실제 이동 중 수신 지연은 기존처럼 정지 요청 대상으로 처리합니다.

현재 환경에서 자동 조회와 터미널 입력 대기 후의 실물 상태 조회는 정상 갱신됐고, 사용자가 겪은 지연이 매번 재현되지는 않았습니다. 따라서 입력 대기가 반드시 CAN 수신을 멈춘다거나 하드웨어가 고장 났다고 판단하지 않습니다. 입력 모드를 바꾼 것은 오래된 캐시와 입력 중 세션 상태에 의존하지 않고 새 피드백을 확보하기 위해서입니다.

재연결 뒤 `최근 관절/상태 피드백이 없습니다`로 중단된 경우도 이동 명령 전 검사 실패입니다. 이전 수정에서는 플랜지 피드백만 기다리고 관절/상태는 한 번 확인해 즉시 중단하는 누락이 있었습니다. 플랜지, 관절, 상태, 각 드라이버는 서로 다른 CAN 메시지이므로 일부만 먼저 들어올 수 있습니다. 현재는 관절/상태/드라이버 전체 수신을 기다리고, 끝내 받지 못하면 **어느 항목이 미수신인지 또는 마지막 수신 후 몇 초인지**를 출력합니다. 피드백 자체는 계속 0.5초 이내여야 하며, 이동이 시작된 후의 수신 지연을 2초까지 허용하는 변경은 아닙니다.

이 SDK는 관절 7개를 4개 메시지에서, 플랜지 6개 값을 3개 메시지에서 합칩니다. 단일 최신 타임스탬프가 나머지 값의 최신성을 보장하지 않아, 예제는 현재 SDK의 각 구성 메시지도 별도로 검사합니다. 일부 관절 쌍이나 X/Y 메시지만 오래됐는데 전체 값이 최신으로 보이는 경우도 차단합니다. 이 검사는 수신 시각 검사이며 모든 메시지의 완전한 동시성을 보장하지는 않습니다.

`마지막 수신 후 -0.000초`는 통신 끊김이 아니라 수신 시각 비교의 문제였습니다. 이 환경의 Python 3.12.9는 Windows `GetSystemTimeAsFileTime()`을 쓰고, 설치된 native CAN 수신 DLL에는 정밀 시계 API가 포함되어 있습니다. 실물 상태 조회에서 2,886회 중 2회 Python 시계 기준 수신 경과 시간이 음수(최소 약 -18마이크로초)였고, 같은 데이터를 `GetSystemTimePreciseAsFileTime()`으로 비교했을 때 음수는 0회였습니다. 정상 수신을 오래된 데이터처럼 거부하는 예제 코드의 버그였습니다.

현재 `nero_feedback_clock.py`는 Windows에서 정밀 시계로 UNIX 시각을 읽고, 모든 예제의 피드백 최신성 검사와 새 프레임 기준 시각을 같은 시계로 통일합니다. 메시지의 원래 수신 시각은 덮어쓰지 않아 큐에서 지연된 데이터를 새 데이터로 취급하지 않습니다. 검사할 타임스탬프를 먼저 복사하고 현재 시각을 읽어 동시 갱신 영향도 줄입니다. 다른 플랫폼에서는 표준 시계를 사용하며, 대기 시간 제한은 계속 monotonic 시계를 사용합니다. 0.5초 이상 지난 실제 지연 데이터, 잘못된 시각과 실제 미래 시각은 계속 거부합니다. Python 업그레이드나 플러그인 수정은 하지 않았습니다.

관련 Python 변경 사항: [Python 3.13 time 변경 내역](https://docs.python.org/3/whatsnew/3.13.html#time). 시간 오차 회귀 테스트는 `tests/test_nero_feedback_clock.py`에 있습니다.

### 같은 XYZ로 가는 여러 방법 중 무엇을 선택하는가?

목적지 위치만으로는 도구 방향이나 관절 자세가 하나로 정해지지 않습니다. 이번 프로그램은 입력된 **XYZ + 이동 직전의 roll/pitch/yaw**를 목표 6개 값으로 만들고 `move_l()`을 요청합니다.

| 결정할 내용 | 현재 프로그램의 처리 |
| --- | --- |
| 목적지 XYZ | 사용자가 입력 |
| 목적지 도구 장착면 방향 | 이동 직전 피드백 방향을 목표에 유지 |
| 플랜지의 이동 경로 | `move_l` 직선 모드로 요청 |
| 그 위치/방향을 만드는 7개 관절의 자세 | 로봇 컨트롤러 내부 IK/운동 계획에서 선택 |

예를 들어 같은 목표에 팔꿈치를 다르게 둔 여러 관절 자세가 가능할 수 있습니다. Python SDK는 목표 자세와 모드 메시지를 보내며, 해당 드라이버의 `move_l(pose)`에는 팔꿈치 자세나 IK 초기 해를 지정하는 인자가 없습니다. **어떤 해를 우선하는지에 대한 컨트롤러 내부 알고리즘은 이 저장소에 없으므로, 항상 가장 가까운 해나 최단 경로를 선택한다고 확정할 수 없습니다.**

`move_l` 요청은 손끝 공간에서 원하는 임의의 우회 경로를 자동 탐색하는 명령이 아닙니다. 예제에는 장애물 모델이나 충돌 회피 계획이 없습니다. 경로를 직접 구성하려면 검증한 중간 지점들을 순서대로 `move_l()`로 연결할 수 있습니다. 관절 자세 자체를 정하려면 검증된 관절 각도 7개를 `move_j()`로 지정할 수 있지만, 이때 플랜지의 직선 경로는 보장되지 않습니다. 장애물 회피나 특정 팔꿈치 자세를 포함한 경로 계획에는 별도의 모델/계획 기능이 필요합니다.

실제로 선택된 자세를 확인할 수 있도록 직선 이동 완료 시 `도착 관절 각도(deg)`를 출력합니다. 이는 실제 관절 피드백이며 경로 전체를 기록한 것은 아닙니다. 펌웨어 1.12의 `get_ik_joint_angles()`도 Cartesian 명령 이후 컨트롤러의 IK 결과를 조회하는 기능이지, 이 프로그램에서 이동 전에 모든 후보를 계산·비교하는 기능은 아닙니다.

**다른 좌표계도 사용할 수 있지만 변환이 필요합니다.** 작업대 모서리를 원점으로 잡거나 카메라가 알려 준 물체 좌표를 사용하려면, 해당 좌표계와 로봇 베이스 사이의 위치·회전 관계를 먼저 구해야 합니다. 이름만 바꿔서 같은 XYZ를 보내면 안 됩니다. 또한 이 예제는 플랜지 기준이며, 실제 그리퍼 끝이나 펜 끝의 목표는 도구 길이와 방향(TCP offset)을 반영해야 합니다. 현재 파일은 사용자 좌표계 보정이나 TCP 설정을 자동 추정하지 않습니다.

자동 검증은 `tests/test_nero_move_to.py`에서 순수 좌표 계산과 가상 CAN을 사용합니다. 이는 좌표 인코딩·상태 검사·도착 확인을 검증하며 실제 작업 공간, 충돌, IK 도달 가능성을 검증하는 시뮬레이터는 아닙니다.

## 4. 구동 명령은 두 가지 기준으로 이해하면 쉽습니다

**관절 기준**은 팔의 각 마디가 몇 도인지 지정하는 것입니다.

```python
# 설명용: 실제로 실행하면 이동 명령을 보냅니다.
target = list(current_joint_angles)
target[6] += math.radians(2)  # J7만 현재보다 +2도
robot.move_j(target)
```

`[j1, j2, j3, j4, j5, j6, j7]` 순서이고 리스트 인덱스는 0부터 시작합니다. `move_j()`의 값은 **절대 목표 각도**입니다. 위 예제처럼 현재 각도에 더해야 상대 이동이 됩니다. `[0] * 7`은 현재 자세 유지가 아니라 모든 관절을 0rad로 보내는 명령입니다. SDK에는 별도의 소프트웨어 각도 제한이 있지만 주변 물체나 자기 충돌까지 막아준다고 볼 수 없습니다.

**위치 기준**은 팔 끝의 위치와 방향을 지정하는 것입니다.

```python
pose = [x, y, z, roll, pitch, yaw]
```

- `x, y, z`: 베이스 기준 위치, 단위 **m**. 1cm는 `0.01`, 5mm는 `0.005`입니다.
- `roll, pitch, yaw`: 방향, 단위 **rad**.
- 기본 이동 함수는 **플랜지**(도구가 붙는 장착면)를 기준으로 합니다. 그리퍼 끝이나 펜 끝과 다릅니다.
- 도구 끝을 기준으로 작업하려면 실제 도구 길이/방향에 맞는 `set_tcp_offset()`과 TCP→플랜지 변환이 필요합니다. TCP offset을 설정했다고 `move_l()` 입력이 자동으로 TCP 좌표가 되는 것은 아닙니다.

| 해보고 싶은 동작 | API | 어떤 움직임인가? |
| --- | --- | --- |
| 관절 하나 살짝 회전 | `move_j(7개 각도)` | 관절 각도로 목표 자세 지정. 첫 움직임에 적합 |
| A 자세 ↔ B 자세 | `move_j()` | 저장한 두 자세를 번갈아 이동. 손끝 경로는 직선 보장 안 됨 |
| 특정 위치로 팔 끝 보내기 | `move_p(위치·방향)` | 목표 자세 지정. 이동 경로는 직선 보장 안 됨 |
| 팔 끝을 위아래/좌우 직선 이동 | `move_l(위치·방향)` | 팔 끝을 직선으로 움직임 |
| 작은 사각형 그리기 | `move_l()` 4회 | 각 꼭짓점까지 이동 완료를 확인하며 실행 |
| 원호 그리기 | `move_c(시작, 중간, 끝)` | 서로 일직선이 아닌 세 위치로 원호 지정 |
| 그리퍼 열기/닫기 | `move_gripper_m()` | 벌림 폭(m)과 힘(N) 지정 |
| 힘/토크, 빠른 관절 추종 | `move_mit()`, `move_js()`, CPV | 이후 단계. 첫 실험에서는 사용하지 않기 |

`move_js()`는 이름이 비슷해도 `move_j()`의 단순 다른 표기가 아닙니다. 코드에서 MIT 모드를 사용하며 부드러운 궤적 계획이 없습니다. 낮은 `set_speed_percent()`만으로 이런 고급 모드의 속도를 제한할 수 있다고 가정하면 안 됩니다.

## 5. 첫 구동: 관절 하나를 2도만 움직이기

**실행 시점의 관절 범위와 시험 자세를 확인한 뒤** 진행하세요. 초기 조회에서 J2/J4 범위 차이가 있었고, 이후 사용자가 보낸 화면에서는 모두 범위 안에 있었습니다. 베이스를 고정하고 팔과 도구가 지나갈 공간을 비운 상태에서 시작합니다. 처음에는 물건을 들지 않고, 장비의 비상정지 절차를 확인해 둡니다. 다른 프로그램이 움직임을 보내고 있지 않은지도 확인하세요.

아래 예제를 프로젝트 루트의 `nero_first_move.py`로 저장할 수 있습니다. 이 파일은 **실행하면 모터를 활성화하고 이동 명령을 보냅니다.** 예제는 J7을 현재보다 2도 이동하며, 현재/목표의 모든 관절이 SDK 범위 안에 있어야 합니다. 범위 밖이면 이동 전에 중단하도록 작성했습니다. 범위 확인은 공간의 안전성을 보장하지 않습니다.

```python
import math
import time
from nero_read_status import connect_nero


def current_angles(robot):
    feedback = robot.get_joint_angles()
    if feedback is None or time.time() - feedback.timestamp > 0.5:
        raise RuntimeError("최근 관절 피드백이 없습니다.")
    return list(feedback.msg)


def check_limits(robot, angles):
    for i, angle in enumerate(angles, 1):
        low, high = robot.get_config()["joint_limits"][f"joint{i}"]
        if not low <= angle <= high:
            raise RuntimeError(f"J{i}가 SDK 범위를 벗어났습니다. 이동하지 않습니다.")


robot, version, profile = connect_nero()
enable_attempted = False
try:
    time.sleep(1)
    check_limits(robot, current_angles(robot))

    # 활성화는 브레이크/제어 상태를 바꿉니다. 무한 재시도하지 않습니다.
    enable_attempted = True
    deadline = time.monotonic() + 5
    while not robot.enable():
        if time.monotonic() >= deadline:
            raise RuntimeError("모터 활성화 실패. 상태를 확인하세요.")
        time.sleep(0.1)

    time.sleep(0.3)
    status = robot.get_arm_status()
    if (status is None or time.time() - status.timestamp > 0.5
            or status.msg.arm_status != 0 or status.msg.ctrl_mode != 1
            or status.msg.motion_status != 0):
        raise RuntimeError("정상 CAN 제어/정지 상태가 아닙니다.")

    start = current_angles(robot)
    check_limits(robot, start)
    target = start.copy()
    target[6] += math.radians(2)
    check_limits(robot, target)

    print("현재(deg):", [round(math.degrees(v), 2) for v in start])
    print("목표(deg):", [round(math.degrees(v), 2) for v in target])
    robot.set_speed_percent(5)  # 위치 제어 속도 비율. 5도/초라는 뜻이 아닙니다.
    robot.move_j(target)

    # 명령 전송은 이동 완료를 뜻하지 않습니다. 상태와 목표 오차를 확인합니다.
    deadline = time.monotonic() + 10
    time.sleep(0.2)
    while True:
        status = robot.get_arm_status()
        angles = current_angles(robot)
        if (status is None or time.time() - status.timestamp > 0.5
                or status.msg.arm_status != 0 or status.msg.ctrl_mode != 1):
            raise RuntimeError("이동 중 상태 이상 또는 상태 피드백 지연")
        error = max(abs(a - b) for a, b in zip(angles, target))
        if status.msg.motion_status == 0 and error < math.radians(0.5):
            print("목표 도착. 자동 복귀하지 않습니다.")
            break
        if time.monotonic() >= deadline:
            raise RuntimeError("도착 확인 시간 초과")
        time.sleep(0.05)
except BaseException:
    if enable_attempted:
        # CAN 통신이 끊겼다면 소프트웨어 정지 명령도 전달되지 않을 수 있습니다.
        robot.electronic_emergency_stop()
    raise
finally:
    # 연결 종료는 모터 비활성화나 정지 명령이 아닙니다.
    # 정상 완료 후 모터를 자동 비활성화하지 않습니다.
    robot.disconnect()
```

```powershell
.\.venv\Scripts\python.exe .\nero_first_move.py
```

7축 관절값은 여러 CAN 프레임을 합쳐 얻습니다. 위 예제의 시간 검사는 SDK 집계값에 대한 검사이며 각 관절 프레임의 완전한 동시성/최신성을 보증하지 않습니다. 이 예제는 작은 수동 실험용이며 안전 컨트롤러가 아닙니다. 여기 적은 이동 코드는 실물에서 실행 검증하지 않았습니다.

## 6. 그다음 시도할 만한 구동

각 예제는 연결·활성화·정상 상태 확인을 마친 `robot` 객체를 전제로 합니다. 이전 동작의 **완료를 확인한 뒤** 다음 명령을 보내세요. `time.sleep()`만으로 도착했다고 판단하지 마세요.

### A. 자세 두 개 저장해서 왕복하기

1. 검증된 조작 방법으로 만든 자세에서 `a = list(robot.get_joint_angles().msg)`로 기록합니다.
2. 작은 관절 이동으로 B 자세를 만들고 같은 방식으로 기록합니다.
3. `robot.move_j(a)` → 도착 확인 → `robot.move_j(b)` → 도착 확인 순서로 한 번만 시도합니다.

이것은 **자세 재현**입니다. 중간 경로까지 손으로 가르치는 드래그 티칭과는 다릅니다. 비활성화된 팔을 억지로 손으로 움직여 자세를 만들지 마세요.

### B. 현재 위치에서 플랜지를 5mm 올리기

작업 공간과 도달 가능 여부를 확인한 시험 자세에서 시작합니다. 관절을 쭉 편 자세 등에서는 작은 직선 이동도 실패할 수 있습니다.

```python
feedback = robot.get_flange_pose()
if feedback is None:
    raise RuntimeError("플랜지 피드백이 없습니다.")
p0 = list(feedback.msg)
p1 = p0.copy()
p1[2] += 0.005
robot.move_l(p1.copy())
# 도착/상태 확인 후 robot.move_l(p0.copy())로 복귀 가능
```

이는 베이스 좌표계 Z 방향으로 올리는 명령입니다. 도구 자체가 향한 방향으로 5mm 미는 명령과는 다릅니다. 위치를 바꾸면 로봇이 필요한 관절 각도를 내부에서 계산합니다. 현재 로컬 SDK의 `get_ik_joint_angles()`는 계산 결과 **피드백 조회**이며, 이동 전에 임의 목표를 검사하는 로컬 IK 해석기는 아닙니다.

### C. 작은 사각형 또는 원호 그리기

공중에서 도구 방향을 고정한 채, 현재 위치를 기준으로 5mm씩 X/Y를 바꾼 네 꼭짓점을 `move_l()`로 연결해 보세요. 그다음 서로 일직선이 아닌 세 위치를 준비해 `move_c(start, mid, end)`로 원호를 만듭니다. 시작점까지의 이동도 별도로 확인해야 합니다. 종이에 펜을 대는 동작은 TCP 길이와 접촉 힘을 다뤄야 하므로 공중 궤적이 안정된 다음에 진행하세요.

### D. 그리퍼 열기/닫기 → 작은 물체 옮기기

실제 장착 그리퍼가 AGX 그리퍼이고 스트로크/영점 상태를 확인한 경우:

```python
gripper = robot.init_effector(robot.OPTIONS.EFFECTOR.AGX_GRIPPER)
gripper.move_gripper_m(value=0.01, force=1.0)  # 예: 10mm 벌림 목표
# 그리퍼 상태를 확인한 뒤 다음 목표를 보냅니다.
```

`value`는 벌림 폭(m), `force`는 명령 힘(N)입니다. 1N은 예시값이며 모든 물체를 잡기에 충분하거나 적절하다는 뜻은 아닙니다. 같은 robot 객체에서 `init_effector()`는 한 번만 호출합니다. 그리퍼 모터 제어와 로봇팔 모터 활성화는 별개이며, `move_gripper_m()` 패킷에는 그리퍼 활성화 상태 코드가 포함됩니다. 처음에는 물체 없이 작은 폭 변화를 확인하세요. 소스의 70mm/100mm 최대 스트로크 설정과 캘리브레이션을 장비 확인 없이 실행하지 마세요.

집기는 `물체 위로 이동 → 천천히 내려가기 → 닫기 → 위로 들기 → 목적지 위로 이동 → 내려놓기 → 열기` 순서입니다. 카메라로 물체를 찾아 자동으로 집으려면 인식·좌표 변환 등 별도 코드가 필요합니다.

## 7. 기존 예제를 그대로 실행하기 전에 알 것

- `pyAgxArm/demos/nero/test1.py`의 `firmware_version = NeroFW.DEFAULT`는 현재 장비와 다릅니다. **`NeroFW.V112`로 바꿔야 합니다.** 설정 함수 인자는 저장소의 실제 철자인 **`firmeware_version`**을 사용합니다.
- `test1.py`의 이동 명령은 대부분 주석이고, 데이터 조회 `while True:` 바로 아래 `break`가 있어 해당 반복문은 즉시 끝납니다. 실행한다고 자동 시험 동작이 나오지 않습니다.
- `pyAgxArm/demos/detect_nero_series.py`는 모니터링 예제지만, 펌웨어 응답을 기다리는 중에 `robot.enable()`을 호출합니다. 그리퍼 데이터도 기다리므로 그리퍼 피드백이 없으면 표시가 진행되지 않을 수 있습니다. 현재 장비의 7번째 관절을 포함하지 않는 6축 표시 부분도 있습니다. 첫 조회에는 `nero_read_status.py`를 사용하세요.
- `move_*()`는 보통 모드를 자동 전환하고 명령을 전송한 뒤 반환합니다. 함수가 끝났다고 물리 이동이 끝난 것은 아닙니다.
- `disable()`은 이동을 안전하게 멈추기 위한 일반 정지 버튼으로 취급하면 안 됩니다. 지지 상태에 따라 팔이 처질 수 있습니다.
- `electronic_emergency_stop()`은 CAN을 통한 감쇠 정지 명령입니다. 통신 상태에 의존합니다. `reset()`은 원점 복귀가 아니며, 문서는 전자 급정지 이후 활성화 상태에서의 복구용으로 설명합니다. 원인을 확인하지 않은 자동 reset/retry는 피하세요.
- 관절 영점 캘리브레이션, 소프트웨어 제한 해제, MIT/JS/CPV 튜닝은 첫 동작에 필요하지 않습니다.

## 8. 연결 문제가 생기면

| 현상 | 먼저 확인할 것 |
| --- | --- |
| `Unknown interface type agx_cando` | 실행 중인 Python이 `.venv`의 Python인지 확인 |
| 채널 열기 실패 | USB-CAN 연결, 채널 번호, 다른 프로그램의 동일 장치 사용 여부 |
| 펌웨어/각도가 `None` | 로봇 전원/초기화, CAN H/L 연결, 1Mbps 설정, 버전별 CAN push 동작 |
| 각도는 보이는데 움직이지 않음 | 모터 활성화, 브레이크/오류 상태, CAN 제어 모드, 목표 도달 가능 여부 |
| `NO_SOLUTION`, `SINGULARITY_POINT` | 다음 목표 전송을 멈추고 목표/시작 자세를 검토. 직선/원호는 중간 경로도 가능해야 함 |
| SDK 제한과 현재 각도가 다름 | 제조사 제어 화면/절차에서 자세와 제한 확인. 임의 영점 재설정이나 제한 해제 금지 |

현재 권장 순서는 **조회 실행 → J2/J4와 시험 자세 확인 → 모터 활성화/정상 CAN 제어 확인 → J7 2도 이동 → 두 자세 왕복 → 5mm 직선 → 공중 도형 → 그리퍼 → 집기**입니다.
